title: Decision

Use System One to classify text, answer yes/no questions, or score text against a rubric.

## Setup

Start [Ollama](/quickstart) v0.35.0 or later, then pull [Nimble](https://ollama.com/library/nimble):

```shell setup.sh
ollama pull nimble
```

## Ask from the terminal

Choose a decision model and ask a yes/no question with `ollama ask`:

```shell
ollama ask nimble "Is water made of hydrogen and oxygen?"
ollama ask nimble "Is this a refund request?" "I was charged twice."
cat ticket.txt | ollama ask nimble "Is this urgent?"
```

The model is the first argument, as with `ollama run`. Give a self-contained question,
or quote the question and additional text as separate arguments. Piped text is read
as one input, including newlines. If you provide a text argument, stdin is ignored.
With no additional text or stdin, the question itself is also the model's input.
Use `ollama pull MODEL` if the model is unavailable.

Supply choices as labels, or as `label=description`. Repeat `--choice` for each:

```shell
ollama ask nimble "Which label fits this ticket?" "Checkout returns 500 errors." \
  --choice 'billing=Payments and refunds' \
  --choice 'bug=Software errors' \
  --choice 'account=Login and account access'
```

For a score, repeat `--score` from the lowest level to the highest:

```shell
ollama ask nimble "How urgently does this need a response?" "Checkout is down." \
  --score 'Routine: no time pressure' \
  --score 'Soon: a customer is inconvenienced' \
  --score 'Immediate: a critical service is unavailable'
```

In a terminal, a yes/no answer displays a percentage, such as `Yes: 99.94%`.
A choice displays the selected label and its probability, and a score displays
its value and scale.
When stdout is redirected, the output is just the yes probability from 0 to 1,
the label, or the numeric score. Use `--json` for the full API response, including
all probabilities and token usage:

```shell
ollama ask nimble "Is this a refund request?" "I was charged twice." --json
```

To ask multiple questions about the same input or customize yes/no criteria, save
the API's `questions` object in a JSON file, then run:

```shell
ollama ask nimble --questions questions.json "I was charged twice."
cat ticket.txt | ollama ask nimble --questions questions.json
```

The file contains named questions with `type`, `instructions`, and `criteria`, as in
the [multiple-question example](#ask-multiple-questions) below. This mode defaults
to the full JSON response when stdout is redirected. `--choice`, `--score`, and
`--questions` are mutually exclusive.

`ollama ask` accepts one input per invocation. To process several independent
texts, run it once per text. Multiple lines on stdin form a single input.

Successful answers exit with status 0, regardless of the probability or score.
Invalid input, unavailable models, and server errors exit nonzero, with diagnostics
on stderr and no answer on stdout. `ollama ask` does not pull missing models automatically.

## Choose a label

Put your input in `state` and describe the possible answers in `criteria`:

```shell choice.sh
curl http://localhost:11434/v1/systemone \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "nimble",
    "state": "Our checkout has returned 500 errors since 9am.",
    "questions": {
      "label": {
        "type": "choice",
        "instructions": "Which label fits this ticket?",
        "criteria": {
          "billing": "Payments and refunds",
          "bug": "Software errors",
          "account": "Login and account access"
        }
      }
    }
  }'
```

Example response:

```json
{
  "model": "nimble",
  "answers": {
    "label": {
      "type": "choice",
      "choice": "bug",
      "probabilities": {"billing": 0.0125, "bug": 0.9781, "account": 0.0093},
      "confidence": 0.8906
    }
  },
  "usage": {"input_tokens": 174, "output_tokens": 1}
}
```

## Question types

| Type | Criteria | Result |
| --- | --- | --- |
| `choice` | 2–26 named options with descriptions | The most likely option and each option's probability |
| `noul` | Descriptions for `"false"` and `"true"` | The probability of `true`, from 0 to 1 |
| `score` | 2–26 descriptions, ordered from lowest to highest | The probability-weighted average of the zero-based levels |

For the urgency criteria below:

```text
score = 0 × P(Routine) + 1 × P(Soon) + 2 × P(Immediate)
```

For `choice` and `score`, `confidence` measures how strongly the model favors one answer over the others, from 0 to 1. A higher value does not guarantee the answer is correct.

## Ask multiple questions

Combine question types in one request. All questions use the same `state`; submit
a separate request for each independent input. Here, both questions use the same
ticket:

```shell multiple.sh
curl http://localhost:11434/v1/systemone \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "nimble",
    "state": {"ticket": "I was charged twice. Please refund the extra payment."},
    "questions": {
      "refund": {
        "type": "noul",
        "instructions": "Is the customer requesting a refund?",
        "criteria": {
          "false": "No refund is requested",
          "true": "The customer requests a refund"
        }
      },
      "urgency": {
        "type": "score",
        "instructions": "How urgently does this ticket need a response?",
        "criteria": [
          "Routine: no time pressure",
          "Soon: a customer is inconvenienced",
          "Immediate: a critical service is unavailable"
        ]
      }
    }
  }'
```

This returns a refund probability of `0.9989` and an urgency score of `0.8308` on the 0–2 scale (rounded). Results can vary with the model and configuration.

See the [API reference](/api/systemone) for request fields, limits, errors, and token usage.
