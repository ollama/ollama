Vision models accept images alongside text so the model can describe, classify, and answer questions about what it sees.

## Quick start

```shell
ollama run gemma4 ./image.png what is in this image?
```


## Usage with Ollama's API
Provide an `images` array. SDKs accept file paths, URLs or raw bytes while the REST API expects base64-encoded image data.


<Tabs>
  <Tab title="cURL">
    ```shell
    # 1. Download a sample image
    curl -L -o test.jpg "https://upload.wikimedia.org/wikipedia/commons/3/3a/Cat03.jpg"

    # 2. Encode the image
    IMG=$(base64 < test.jpg | tr -d '\n')

    # 3. Send it to Ollama
    curl -X POST http://localhost:11434/api/chat \
    -H "Content-Type: application/json" \
    -d '{
        "model": "gemma4",
        "messages": [{
        "role": "user",
        "content": "What is in this image?",
        "images": ["'"$IMG"'"]
        }],
        "stream": false
    }'
    ```
  </Tab>
  <Tab title="Python">
    ```python
    from ollama import chat
    # from pathlib import Path

    # Pass in the path to the image
    path = input('Please enter the path to the image: ')

    # You can also pass in base64 encoded image data
    # img = base64.b64encode(Path(path).read_bytes()).decode()
    # or the raw bytes
    # img = Path(path).read_bytes()

    response = chat(
      model='gemma4',
      messages=[
        {
          'role': 'user',
          'content': 'What is in this image? Be concise.',
          'images': [path],
        }
      ],
    )

    print(response.message.content)
    ```
  </Tab>

    ```javascript
      ],

    })

    console.log(response.message.content)
    ```

## Video input

Local multimodal GGUF models with video support, such as `qwen3-vl` and
`qwen2.5vl`, accept base64-encoded files in `videos`. The runner samples frames
and preserves their temporal order. Start with a short clip and allow enough
context for the sampled frames. MLX models do not support this input.

The bundled decoder supports H.264, HEVC, and VP9 in MP4/MOV, WebM/Matroska,
and AVI containers. Container extensions alone do not determine the codec.
No system FFmpeg installation is required. In the desktop app, attach a video
file as you would an image.

```python
import base64
import json
import urllib.request

with open("clip.mp4", "rb") as clip:
    video = base64.b64encode(clip.read()).decode("ascii")

request = urllib.request.Request(
    "http://localhost:11434/api/chat",
    data=json.dumps({
        "model": "qwen3-vl:2b",
        "messages": [{"role": "user", "content": "Describe what changes in this clip.", "videos": [video]}],
        "stream": False,
    }).encode(),
    headers={"Content-Type": "application/json"},
)
with urllib.request.urlopen(request) as response:
    print(json.load(response)["message"]["content"])
```

`/api/generate` accepts the same `videos` array alongside `prompt`.
`/v1/chat/completions` accepts a content part with
`{"type": "video_url", "video_url": {"url": "data:video/mp4;base64,..."}}`.
Video URLs must be inline base64 data URLs; download remote videos before sending
them to Ollama. Images and videos can be combined in the same message; images
precede videos when both arrays are supplied.
